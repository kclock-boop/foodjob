한끼 · 기업 식수관리
설치 및 운영 안내 v1.0

시작 파일: index.html · HTML / CSS / JavaScript · Supabase 인증·DB · GitHub 저장 · Netlify 배포

프로그램 연결 값은 Project URL과 Publishable key(또는 legacy anon key) 두 가지입니다. 단, 신규 Supabase 프로젝트에는 최초 1회 데이터베이스 SQL 실행과 최초 관리자 지정이 필요합니다. 키만으로 테이블을 자동 생성하지 않습니다.

1. 먼저 체험하기

  1. ZIP을 풀고 meal-manager 폴더를 엽니다.
  2. index.html을 Chrome 또는 Edge로 엽니다.
  3. ‘설정 없이 체험하기’를 누릅니다. 예시 데이터로 식수 저장·날짜 변경·마감·운영 상태·CSV·인쇄 기능을 살펴봅니다.

인터넷 연결이 필요합니다(Supabase JS CDN). 파일 직접 열기에서 브라우저 보안 제한이 생기면 VS Code Live Server로 열거나 Netlify에 먼저 배포하세요. 실제 로그인·공유 검증은 https Netlify 주소에서 수행하세요. 체험 데이터는 탭의 sessionStorage에만 저장되며 실제 DB로 이전되지 않습니다.

2. Supabase 프로젝트 만들기

  1. Supabase Dashboard에 가입·로그인합니다.
  2. New project로 기업용 프로젝트를 하나 생성합니다. DB 비밀번호는 안전한 곳에 보관합니다.
  3. 프로젝트가 준비되면 왼쪽 SQL Editor → New query를 엽니다.
  4. 첨부 setup.sql을 메모장으로 열고 전체 내용을 복사해 붙여넣은 뒤 Run을 누릅니다.
  5. Success를 확인합니다. 이 SQL은 신규 프로젝트용입니다. 이미 실행된 프로젝트에는 재실행하지 않습니다. 오류 발생 시 첫 오류를 확인하며 기존 데이터베이스를 삭제하지 마세요.
  6. Project Settings / API 또는 Connect 화면에서 Project URL, API Keys 화면에서 Publishable key를 복사합니다. legacy anon key도 지원합니다.

Secret key, service_role key, 데이터베이스 비밀번호는 config.js에 입력하지 않습니다. 공개 키는 웹앱에 공개되는 값이며 실제 접근 권한은 로그인·RLS·서버 함수로 제한됩니다.

3. 연결 값 등록하기

  1. index.html → 연결 설정을 엽니다.
  2. URL과 공개 키를 붙여넣습니다.
  3. ‘config.js 다운로드’를 눌러 받은 파일을 프로그램 폴더의 기존 config.js와 교체합니다. 이렇게 하면 다른 PC도 같은 프로젝트에 연결됩니다.
  4. 현재 브라우저에도 적용하려면 ‘저장 · 로그인으로’를 누릅니다.
window.MEAL_CONFIG = {
  url: 'https://프로젝트ID.supabase.co',
  key: 'sb_publishable_실제공개키'
};

브라우저에서 저장한 값이 config.js보다 우선합니다. 프로젝트를 변경했다면 연결 설정에서 새 값을 다시 저장하세요. 키가 들어간 파일을 만들 때도 공개 키만 사용하세요.

4. GitHub → Netlify 배포

  1. GitHub에서 새 저장소를 만듭니다(예: company-meal-manager). 비공개 저장소를 권장합니다.
  2. GitHub Desktop에서 저장소를 Clone합니다.
  3. 저장소 폴더 안에 index.html, app.js, style.css, config.js, netlify.toml, setup.sql, 설치안내.html 등 ZIP의 meal-manager 내부 파일을 복사합니다. 저장소 최상위에 index.html이 있어야 합니다.
  4. GitHub Desktop → Summary 입력 → Commit → Push origin을 누릅니다.
  5. Netlify 로그인 → Add new project → Import an existing project → GitHub 선택 → 저장소 선택.
  6. 배포 설정: Base directory 비움, Build command 비움, Publish directory . (마침표 한 개). 첨부 netlify.toml에도 같은 설정이 있습니다.
  7. Deploy 후 Published 상태를 확인하고 생성된 https 주소로 접속합니다.
  8. 이후 파일 수정 → Commit → Push하면 Netlify가 새 버전을 배포합니다.

5. 최초 관리자 등록

  1. Supabase → Authentication → URL Configuration에서 Site URL을 실제 Netlify 주소로 지정합니다. 필요한 Redirect URL에도 같은 사이트 주소를 추가합니다.
  2. 배포된 앱의 회원가입에서 관리자 본인 이름·이메일·비밀번호(8자 이상)를 입력합니다.
  3. 이메일 인증이 활성화되어 있으면 수신 메일의 확인 링크를 누릅니다. 메일 미수신·발송 제한은 Supabase 이메일 제공자 및 SMTP 설정을 확인합니다.
  4. Supabase SQL Editor에서 아래 이메일을 실제로 가입한 관리자 이메일로 바꿔 실행합니다.
update public.profiles
set role = 'admin', active = true
where email = '실제관리자이메일@example.com'
returning id, name, email, role, active;

결과가 1행인지 확인하세요. 0행이면 앱 회원가입이 완료되었는지, 이메일이 맞는지 확인합니다. 최초 관리자 계정은 자동으로 임의 승격되지 않습니다. 기존 Auth 사용자는 setup.sql 설치 이후 앱에서 새 계정을 가입하는 방법을 사용하세요.

  1. 앱에서 로그인합니다. 이미 로그인했다면 ‘승인 상태 확인’을 누릅니다.
  2. 다른 직원은 본인 이메일로 회원가입합니다.
  3. 관리자 → 사용자 관리에서 활성 체크, 일반사용자/관리자 선택, 담당 부서 지정 후 저장합니다.

6. 권한 및 일일 업무

기능관리자일반사용자
식수 조회·입력전체 부서배정된 한 부서
식당·차량조회·설정조회
날짜 마감·해제가능불가
사용자 승인·권한·부서 배정가능(본인 제외)불가
부서 추가·변경 이력가능불가
CSV·인쇄전체 식수담당 부서 식수

식수 입력 → 날짜 선택 → 해당 부서의 주간·야간 식수·상세 입력 → 행별 저장. 여러 행을 한꺼번에 입력하지 말고 한 행씩 저장하세요. 행 저장 후 화면을 다시 불러오므로 다른 행의 미저장 입력은 유지되지 않습니다.

식당·차량 메뉴에서 관리자는 중식·석식·야식 운영과 창원1·창원2·마산·진해·김해/부산 주간·야간 운행을 선택합니다. 선택 즉시 저장됩니다. 아직 선택하지 않은 상태는 ‘미설정’입니다.

전체 확인 후 날짜 마감. 마감 후에는 관리자도 직접 수정할 수 없으며 마감 해제 후 저장합니다. 동시 수정 충돌은 저장을 거부하므로 새로고침 후 다시 입력합니다. 최신 데이터는 새로고침 버튼이나 날짜 변경으로 읽습니다(자동 실시간 갱신 아님).

원본 이미지의 하단이 잘려 있어 보이지 않는 부서는 추정하지 않았습니다. 기본 등록된 생산1팀·생산2팀 등의 행은 독립 입력 부서입니다. 생산1팀이 하위 부서 합계를 뜻한다면 생산1팀 행에 중복 입력하지 마세요. 합계는 입력된 모든 부서의 인원을 합산합니다. 주간·야간과 중식·석식·야식 운영 여부는 별도 관리하며 식사 종류별 개인 신청 기능은 포함하지 않습니다.

7. 출력·운영 관리

  • CSV: 선택 날짜의 식수와 운영 정보를 UTF-8 BOM 형식으로 내려받습니다. Excel에서 열 수 있습니다.
  • 인쇄 / PDF: 브라우저 인쇄창에서 PDF로 저장, 가로 방향을 선택합니다.
  • 비밀번호 분실: 관리자가 Supabase Authentication → Users에서 해당 사용자를 확인하고 비밀번호 재설정/복구 절차를 진행합니다. 관리자는 기존 비밀번호를 볼 수 없습니다.
  • 비활성화: 사용자 관리에서 활성 체크 해제. 기존 로그인 상태라도 DB 권한 검사로 업무 데이터 접근을 차단합니다.
  • 이력: 식수·운영·마감·사용자 권한 변경은 audit 테이블에 기록됩니다. 앱에는 최근 100건을 표시합니다. 부서 추가는 별도 audit 기록 대상이 아닙니다.
  • 데이터 백업: Supabase의 프로젝트 백업/내보내기 정책을 확인하고 회사 운영 기준에 맞게 보관합니다.

8. 설치 후 필수 확인

  1. 관리자와 일반사용자를 각각 가입시킵니다.
  2. 일반사용자를 활성화하고 하나의 부서를 배정합니다.
  3. 일반사용자가 해당 부서 식수만 조회·저장하는지 확인합니다.
  4. 다른 PC에서 관리자로 접속해 같은 데이터를 확인합니다.
  5. 날짜를 마감하고 일반사용자가 저장할 수 없는지 확인합니다.
  6. 마감 해제 후 재수정하고 변경 이력을 확인합니다.
  7. 같은 부서·날짜를 두 창에서 연 뒤 한쪽에서 저장하고, 다른 창에서 저장 시 충돌 안내를 확인합니다.

납품 환경에서는 실제 기업의 Supabase 키·계정이 제공되지 않아 실제 Supabase 로그인, RLS 실행, 다중 PC 연동 및 Netlify 배포 검증은 수행하지 않았습니다. 파일의 JavaScript 문법·일부 화면 로직 및 로컬 체험 동작을 검토했습니다. 운영 전 위 확인 절차를 수행하세요.
